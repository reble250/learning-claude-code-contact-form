# お問い合わせフォーム 仕様書

## 1. プロジェクト概要
Laravelで構築するお問い合わせフォーム。エンドユーザーが利用する「お問い合わせフォーム」と、管理者が利用する「管理画面」からなる。

- フレームワーク: Laravel 13 (PHP 8.3)
- データベース: SQLite
- フロントエンド: Blade + Tailwind CSS v4（Vite）
- ロケール: `ja`（`APP_LOCALE=ja`、フォールバックは`en`）
- 管理画面の認証: あり（`web`ガード、ログイン必須。詳細は5.4節）

## 2. データベース仕様

### `contacts` テーブル
マイグレーション: `database/migrations/2026_07_31_020637_create_contacts_table.php`

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| id | bigIncrements | PK | 主キー |
| name | string | not null | 名前 |
| email | string | not null | メールアドレス |
| subject | string | not null | 件名 |
| body | text | not null | 本文 |
| status | string | not null, default: `new` | 対応ステータス |
| ip_address | string(45) | nullable | 送信者IPアドレス（IPv4/IPv6対応） |
| user_agent | string | nullable | 送信者User-Agent |
| created_at | timestamp | - | 受付日時 |
| updated_at | timestamp | - | 更新日時 |

### ステータス（`App\Enums\ContactStatus`）
文字列バックの enum。DBには`value`が保存され、`Contact`モデルで自動的にenumへキャストされる。

| enum値 | value | 日本語ラベル | バッジ色 |
|---|---|---|---|
| `New` | `new` | 新規 | 青 |
| `InProgress` | `in_progress` | 対応中 | 黄 |
| `Resolved` | `resolved` | 解決済み | 緑 |

### `Contact` モデル（`app/Models/Contact.php`）
- `$fillable`: `name`, `email`, `subject`, `body`, `status`, `ip_address`, `user_agent`
- `casts()`: `status` を `ContactStatus` enumにキャスト

## 4. お問い合わせフォームの仕様

### 4.1 画面フロー
```
入力画面 (GET /contact)
  └─ 送信 → 確認画面 (POST /contact/confirm) ─┬─ 戻る → 入力画面（入力内容保持）
                                                └─ 送信する → 保存 (POST /contact) → 完了画面 (GET /contact/thanks)
```

- 確認画面（`resources/views/contact/confirm.blade.php`）は1つの`<form>`内に隠しフィールド（name/email/subject/body）を保持し、「戻る」「送信する」の2つの送信ボタンがそれぞれ異なる`formaction`（`contact.back` / `contact.store`）を持つ。
- 「戻る」時は`ContactController@back`が入力値を`withInput()`で入力画面にリダイレクトし、入力内容を保持する。
- 完了画面はセッションに一時的なフラグ（`contact.submitted`）が立っている場合のみ表示される。フラグが無い状態で直接`/contact/thanks`にアクセスすると入力画面へリダイレクトされる（`session()->pull()`で1回読むと消える、いわゆるPost/Redirect/Getガード）。

### 4.2 入力バリデーション（`app/Http/Requests/ContactRequest.php`）

`confirm`・`store`の両アクションで同一のルールを適用（`store`でも再度サーバーサイド検証される）。

| 項目 | フィールド名 | ルール | エラーメッセージ |
|---|---|---|---|
| 名前 | `name` | `required`, `string`, `max:255` | 「名前を入力してください。」/「名前は255文字以内で入力してください。」 |
| メールアドレス | `email` | `required`, `string`, `email`, `max:255` | 「メールアドレスを入力してください。」/「メールアドレスの形式で入力してください。」/「メールアドレスは255文字以内で入力してください。」 |
| 件名 | `subject` | `required`, `string`, `max:255` | 「件名を入力してください。」/「件名は255文字以内で入力してください。」 |
| 本文 | `body` | `required`, `string`, `max:2000` | 「本文を入力してください。」/「本文は2000文字以内で入力してください。」 |

- `email`ルールはLaravel標準の形式チェックのみ（DNS/MXレコードの実在確認は行わない）。
- バリデーションエラー時は入力画面へ`withErrors`＋`withInput`でリダイレクトされ、`@if ($errors->any())`で一覧表示される。

### 4.3 保存時の付加情報
`store()`実行時、バリデーション済みデータに加えて以下をリクエストから自動付与する。
- `ip_address`: `$request->ip()`
- `user_agent`: `$request->userAgent()`
- `status`: 未指定のためDBのdefault値`new`（新規）が適用される

## 5. 管理画面の仕様

### 5.1 一覧画面（`resources/views/admin/contacts/index.blade.php`）
- `Contact::query()->latest()->paginate(20)->withQueryString()` で新着順・20件ずつページネーション表示（検索条件はページネーションリンクにも引き継がれる）
- 表示項目: 受付日時、名前、件名、ステータス（バッジ表示）
- 各行クリックで詳細画面へ遷移
- 0件の場合、検索条件なしなら「お問い合わせはまだありません。」、検索条件ありなら「該当するお問い合わせが見つかりません。」を表示

#### 検索・絞り込み（GETクエリパラメータ）
`Admin\ContactController@index` でバリデーション後、`when()`によりAND条件で絞り込む。

| 項目 | パラメータ | 条件 | 備考 |
|---|---|---|---|
| 氏名 | `name` | `LIKE '%値%'`（部分一致） | `nullable`, `string`, `max:255` |
| 受付日時（从） | `date_from` | `whereDate('created_at', '>=', 値)` | `nullable`, `date` |
| 受付日時（至） | `date_to` | `whereDate('created_at', '<=', 値)` | `nullable`, `date` |
| ステータス | `status[]` | `whereIn('status', 値)`（複数選択時はOR） | `nullable`, `array`。各要素は`ContactStatus`enumの値のみ許可 |

氏名・期間・ステータスの各条件は互いにAND結合される（例: 氏名かつ期間内かつ選択ステータスのいずれか）。検索フォームには現在の検索条件が保持され、「クリア」リンクで条件なしの一覧に戻れる。

### 5.2 詳細画面（`resources/views/admin/contacts/show.blade.php`）
- 表示項目: 受付日時、名前、メールアドレス、件名、本文（全文）
- ステータス変更用のドロップダウン（`<select>`）とフォームを表示
  - 選択肢は`ContactStatus::cases()`から生成（新規／対応中／解決済み）
  - `PATCH /admin/contacts/{contact}`へ送信
  - 更新成功時はセッションフラッシュ（`status_updated`）により「ステータスを更新しました。」を表示

### 5.3 ステータス更新のバリデーション（`Admin\ContactController@update`）
- `status`: `required`, `Rule::enum(ContactStatus::class)`（enumの定義値以外は拒否）

### 5.4 認証
`/admin/contacts`配下は`auth`ミドルウェアで保護されており、ログインが必要。

- ガード: `web`（`config/auth.php`のデフォルト）、ユーザーモデルは既存の`App\Models\User`・`users`テーブルを利用
- ログイン: `app/Http/Controllers/Auth/LoginController.php`
  - `GET /login`（`login`）: ログインフォーム表示（`resources/views/auth/login.blade.php`）
  - `POST /login`（`login.store`）: `email`/`password`をバリデーションし`Auth::attempt()`。ブルートフォース対策として`throttle:5,1`（1分間に5回まで）を適用。失敗時はログイン画面にエラーメッセージを表示
  - `POST /logout`（`logout`）: `Auth::logout()`とセッション無効化・トークン再生成
  - 未ログイン状態で保護対象ルートにアクセスすると`/login`へリダイレクトされ、ログイン成功後は元のURL（`intended`）、指定が無ければ`admin.contacts.index`へ遷移する
- 管理画面レイアウト（`resources/views/layouts/admin.blade.php`）にログアウトボタンを設置（ログイン時のみ表示）
- 管理者アカウントの作成: `database/seeders/AdminUserSeeder.php`が`.env`の`ADMIN_EMAIL`/`ADMIN_PASSWORD`（未設定時はデフォルト値`admin@example.com`/`password`）から`User::updateOrCreate()`でアカウントを作成する。`php artisan db:seed --class=AdminUserSeeder`または`php artisan db:seed`（`DatabaseSeeder`経由）で実行
- 新規ユーザー登録・パスワードリセット画面は用意していない（管理者アカウントはseederでのみ作成する運用）

### 5.5 開発用ダミーデータ
動作確認・検索機能の確認用に、お問い合わせのダミーデータを100件投入するSeederを用意している。

- `database/factories/ContactFactory.php`: 氏名（姓＋性別別の名をランダム組み合わせ）、`@example.com`のメールアドレス、ショッピングサイトを想定した件名・本文（注文未着・返品・サイズ交換など16パターン）、ステータス（3種からランダム）、過去3ヶ月以内のランダムな`created_at`を生成
  - `male()` / `female()` ステートで性別を指定可能
- `database/seeders/ContactSeeder.php`: `male()`50件・`female()`50件をそれぞれ作成し、男女比を必ず半々にする
- 実行方法: `php artisan db:seed --class=ContactSeeder`（`DatabaseSeeder`には登録していないため、`php artisan db:seed`実行時には投入されない。実行のたびに100件が追加される非冪等な処理のため、本番環境では使用しないこと）

### 5.6 CSVエクスポート
`Admin\ContactController@export`（`GET /admin/contacts/export`）でお問い合わせ一覧をCSVダウンロードできる。

- 認証: 他の管理画面ルートと同様`auth`ミドルウェアで保護（未ログイン時は`/login`へリダイレクト）
- 絞り込み: `status`クエリパラメータ（単一値、例: `?status=new`）でステータスを絞り込み可能。値は`ContactStatus`enumのいずれかのみ許可（`Rule::in()`でバリデーション）
- 出力形式: UTF-8 BOM付きCSV。ヘッダー行は`ID, 名前, メールアドレス, 件名, ステータス, 受信日時`（ステータスは`ContactStatus::label()`による日本語ラベル、受信日時は`created_at`を`Y-m-d H:i:s`形式で出力）
- 実装: `response()->streamDownload()`によるストリーミングダウンロード。ファイル名は`contacts_YmdHis.csv`
- ルート定義順序の注意: `export`は`{contact}`ワイルドカードより前に登録する必要がある（後ろだと`export`がお問い合わせIDとして解釈され404になる）
- 対応テスト: `tests/Feature/CSVExportTest.php`（6テスト）
